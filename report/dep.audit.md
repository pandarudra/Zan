```ts

```

- ✅ Reads `process.env.PORT` — Render injects this automatically.
- ⚠️ **Missing host binding.** `server.listen(PORT)` defaults to `0.0.0.0` on Node.js — this is fine. No explicit `'0.0.0.0'` argument needed.

### CORS

```ts
cors({
  origin: process.env.ALLOWED_ORIGINS?.split(",") ?? [
    "http://localhost:3000",
    "http://localhost:3001",
  ],
  credentials: true,

```

- **BLOCKER**: If `ALLOWED_ORIGINS` is not set on Render, the fallback whitelist is localhost-only. All cross-origin requests from Vercel will be rejected with CORS error.
- Must set `ALLOWED_ORIGINS=https://your-app.vercel.app` on Render.

`waitForDependencies()` polls DB and Redis with infinite retry loops before the HTTP server starts. This is safe for production but means Render's health check will time out if DB or Redis is unavailable. Ensure Render's health check grace period is sufficient (≥ 60s).

## Phase 5 — Database / Prisma Audit

### Versions

- `prisma` CLI: `^7.7.0` (devDep in `@repo/db`)
- `@prisma/client`: `^7.7.0`
- `@prisma/adapter-pg`: `^7.7.0` (driver adapter — **not** classic Prisma client)

### Schema & Generation

- Schema: `packages/db/prisma/schema.prisma`
- `generator client { provider = "prisma-client"; output = "../generated/prisma" }`
- Uses `previewFeatures = ["driverAdapters"]` — this is the newer Prisma 5+ driver adapter pattern
- Generation command: `prisma generate` (run from `packages/db/`)
- `@repo/db` build script: `"prisma generate && tsc"` — generation is part of build ✅

### `prisma.config.ts` behavior

```ts
datasource: {
  url: process.env["DIRECT_URL"] || process.env["DATABASE_URL"],
}
```

Uses `DIRECT_URL` first, falling back to `DATABASE_URL`. For Supabase with connection pooling, you typically use:

- `DATABASE_URL` → pooled connection (PgBouncer, port 6543)
- `DIRECT_URL` → direct connection (port 5432, required for migrations)

### `packages/db/index.ts` DB instantiation

```ts
const connectionString = process.env.DATABASE_URL?.trim();
if (!connectionString) throw new Error(`DATABASE_URL is not set...`);
```

Throws hard at import time if `DATABASE_URL` is missing. ✅

### Migration Location

`packages/db/prisma/migrations/` — 4 migration files committed ✅

### Safe Production Migration Strategy

```bash
# 1. Run from monorepo root — targets @repo/db package
pnpm --filter @repo/db exec prisma migrate deploy

# This command:
# - Applies all pending migrations from prisma/migrations/
# - NEVER resets data (unlike prisma migrate reset — which must NEVER be used in production)
# - Is idempotent — safe to re-run
# - Requires DIRECT_URL or DATABASE_URL pointing to the database
```

> [!CAUTION]
> Never run `prisma migrate reset` in production. It drops and recreates the database.

### Committed Artifact Issue

`packages/db/index.js` is tracked in git. The package exports from `dist/index.js` (the real compiled output). The root `index.js` is a stale artefact and should be removed from git tracking.

## Phase 8 — Final Report

### Production Readiness Score: **5.5 / 10**

The application is architecturally sound with a clean monorepo structure, Turbo pipeline, proper JWT auth, health endpoint, graceful shutdown, and Redis job queue. The blockers are all configuration-level, not architectural — no rewrites required.

---

### 🔴 BLOCKERS (deployment will fail or be insecure)

1. **`ALLOWED_ORIGINS` missing on Render** — CORS fallback is `localhost`. Every request from Vercel will be rejected with a CORS error. Set `ALLOWED_ORIGINS=https://your-app.vercel.app`.
2. **`NEXTAUTH_SECRET=your-secret-here`** committed as placeholder in `apps/web/.env`. Must be replaced with a real secret before deployment.
3. **`packages/db/.env` contains live Supabase credentials** that are gitignored locally but should be audited to ensure no branch has ever committed this file.
4. **Root `.env` contains live Azure Account Key, Upstash Redis URL, and Solana private keypair** in plaintext. While gitignored, this file must be rotated after confirming it was never committed on any branch (`git log --all -- .env`).
5. **`NEXTAUTH_URL` hardcoded to `http://localhost:3000`** in `apps/web/.env`. NextAuth will generate incorrect callback URLs on Vercel. Must be set to the production domain.

---

### 🟠 HIGH Priority

6. **`packages/db/index.js` is tracked in git** — a stale compiled artifact. Run `git rm packages/db/index.js` and add `packages/db/index.js` to `.gitignore`. The real compiled output is `packages/db/dist/index.js`.
7. **`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` in `turbo.json`** env cache array but **no Google OAuth provider in `lib/auth.ts`**. Either remove from turbo.json (dead config) or implement the provider. Dead env vars in turbo.json cause unnecessary cache misses.
8. **`allowedDevOrigins: ["vercel.com"]` in `next.config.js`** — this is a `next dev` only option and should be removed from production config. It's noise that obscures real configuration.
9. **Web app directly accesses DB (`@repo/db`)** in 3 route handlers — this is architecturally fine but means `DATABASE_URL` is required on Vercel. Document this clearly and ensure it's set.
10. **Web app directly uses Redis** (`lib/jobQueue.ts`) — `REDIS_URL` required on Vercel. This creates an architectural coupling: the frontend is not truly stateless.

---

### 🟡 MEDIUM

11. **`pino-pretty` is a production dependency** in `apps/server`. It should be a `devDependency`. In production, plain pino JSON output is better and `pino-pretty` adds unnecessary size.
12. **Server health check grace period** — `waitForDependencies()` polls DB and Redis indefinitely before the HTTP server starts. Render's default health check timeout may expire before the server is ready if DB is slow. Set Render health check grace period to ≥ 60s.
13. **`DIRECT_URL` not set on Render** — `prisma.config.ts` prefers `DIRECT_URL` for migrations. On Supabase, migrations must run against the direct connection (port 5432), not the pooler. Set both `DATABASE_URL` (pooler) and `DIRECT_URL` (direct) on Render.
14. **`SERVER_URL=http://localhost:3001`** in root `.env` — not referenced in any server source code. Likely dead or agent-only. Verify before removing.

---

### 🟢 LOW

15. **`explain.log`** in `packages/crypto/` — debug artifact, safe to delete and gitignore.
16. **`full-context.txt`** in root — LLM context file, not needed in repo. Add to `.gitignore`.
17. **`SOLANA_RPC_URL` currently points to devnet** in `.env`. For production, switch to mainnet or a paid RPC provider (Helius, QuickNode, etc.).
18. **`NEXT_PUBLIC_ESCROW_PROGRAM_ID` hardcoded fallback** in `use-escrow.ts` to devnet program ID. Set the env var explicitly so the fallback is never relied upon in production.

### Recommended Deployment Order

```
Step 1 — Rotate & provision secrets
  → Generate NEXTAUTH_SECRET, JWT_SECRET, INTERNAL_SECRET
  → Confirm DATABASE_URL / DIRECT_URL for production Supabase
  → Confirm REDIS_URL for production Upstash
  → Confirm AZURE credentials for production

Step 2 — Apply database migrations
  → pnpm --filter @repo/db exec prisma migrate deploy
  → (uses DIRECT_URL → Supabase direct connection)

Step 3 — Deploy Render (server)
  → Set all Render env vars
  → Set ALLOWED_ORIGINS to Vercel URL (get from Step 4 if first deploy)
  → Verify /api/health returns 200

Step 4 — Deploy Vercel (web)
  → Set NEXT_PUBLIC_API_URL to Render service URL
  → Set NEXTAUTH_URL to Vercel deployment URL
  → Set all other env vars
  → Trigger deployment

Step 5 — Smoke test
  → Register a user → Login → Connect wallet → Submit a job
```
